# Spine Pair Review — Peerless

## Overall verdict
The pair is a rigorous contract. Every `{path.to.token}` reference resolves, the DESIGN.md sections follow the canonical order, the vocabulary is decided, and the flow arithmetic was re-checked and is exact (1 170 000; 1 752 531; 212 807; waterfall 267 429 = 83 571 → 351 000). A consumer still cannot extract it cleanly. Dark mode is half-specified: tokens exist, pairs are missing, and nothing says whether it ships. Two states on the primary surface and the URL-validation contract are missing. The declared copy source (`messages-v1.nb.json`) holds superseded strings, and PRD FR-73 contradicts the spine's outside-seed state. Fix these, and index the scattered load-bearing `[ASSUMPTION]`s, before story-dev starts.

## 1. Flow coverage — adequate
Checked against `sources` → PRD §2.3. UJ-1 and UJ-2 (v1) each have a Key Flow with a verbatim title, a named protagonist, numbered steps, a bold climax and a failure or edge path. Flow 3 (phone) and Flow 4 (decomposition) fill the two gaps the memlog asked for. UJ-3 and UJ-4 are stage 2 and correctly have no flow. The climax figures were recomputed and match.
### Findings
- **[medium]** UJ-1 step 3 excludes two peers, which per FR-19 recomputes every aggregate and tags the explanation as written for the standard group. Yet the Key Flows intro says "Figures are for the default peer group", and the step-5 climax quotes default-group median, beste fjerdedel and kroner. A consumer turning the flow into an e2e fixture gets contradictory state (EXPERIENCE Key Flows intro; UJ-1 steps 3–5). *Fix:* move the exclusion after the climax, or state the post-exclusion figures and the explanation's tagged state.
- **[medium]** The Surface closure table credits flows that do not exercise the surface. "How it works, can I trust it" points to UJ-1, but no flow visits Slik fungerer Peerless. "Trace any kroner amount" points to Flow 4 and UJ-2, but only Flow 3 opens the provenance drill-down (EXPERIENCE IA → Surface closure). *Fix:* correct the journey column, or add a step to UJ-1 that opens Slik fungerer Peerless.
- **[low]** UJ-3 and UJ-4 are never named as deliberately absent. Later stages lists their features but not their ids (EXPERIENCE Later stages). *Fix:* add one line: "UJ-3 and UJ-4 are stage 2; no v1 flow."

## 2. Token completeness — thin
I extracted 30 colour, 13 typography, 4 rounded, 7 spacing and 15 component tokens, and every prose reference in both files: `{colors.navy-700}`, `{colors.favourable}`, `{colors.unfavourable}`, `{components.marker-*}`, `{components.tooltip.shadow}`, `{spacing.*}`, `{rounded.*}` and `{typography.body}`. All are defined. Every colour has a hex value, and contrast is stated for the marker, the input border, the median and every text pair the memlog verified.
### Findings
- **[critical]** Light/dark pairs are missing although dark tokens are defined. `surface` has no dark value, and it carries group rows, banners, state blocks, calculation chips, the disabled step, the search loading fill and the highlighted search result. `peer-dot`, `gridline` and `disabled-text` have no dark values either. DESIGN Colors "Gaps" admits this (DESIGN frontmatter `colors`; Colors → Gaps). *Fix:* define `surface-dark`, `peer-dot-dark`, `gridline-dark` and `disabled-text-dark` with verified contrast. Alternatively, declare dark mode out of v1 and move the dark tokens to Later stages.
- **[high]** Dark mode's scope and mechanism are uncommitted. No spine says whether v1 ships dark, or whether it follows `prefers-color-scheme` or a toggle. Only `marker-company` and `marker-median` have dark component mappings: `card`, `header`, `tooltip`, `state-block`, `waterfall-bar`, `segmented-control` and `search-field` (its `focus-ring` uses `{colors.background}`) have none. Pair naming is irregular: `navy-900`↔`text-dark`, `navy-700`↔`primary-dark`, `slate`↔`muted-dark`, `card`↔`card-dark`. A resolver cannot pair them mechanically (DESIGN frontmatter; EXPERIENCE Foundation is silent). *Fix:* make the call in EXPERIENCE Foundation. If dark ships, name pairs `x` / `x-dark` and add `-dark` keys to every component.
- **[high]** `disabled-text` `#6F7E90` measures 4.15:1 on white and 3.86:1 on `surface`, which fails AA 4.5:1. It is the text colour of excluded peer rows, and those rows are content, still actionable through "Ta med igjen", so the disabled-control exemption does not apply. DESIGN Colors claims "all light and dark text pairs pass AA" (DESIGN Colors → Verified contrast; Components → Peer list). *Fix:* use `slate` (5.08:1 on `surface`) for excluded rows and carry exclusion by strikethrough plus the "Ekskludert" tag. Keep `disabled-text` for the disabled step only, and verify it.
- **[medium]** Raw values sit outside the token set. Hex values: `#FBFCFD` (fold-out body, Elevation; Components → Fold-out) and `#B9C3CF` (waterfall connectors). Off-scale values: tooltip radius `5px`, `waterfall-bar.data-end-radius: 4px`, tooltip shadow `rgba(11,35,64,.14)`. The peer dot's "2px white stroke" is fixed white, so it fails in dark mode (Shapes table). *Fix:* add `surface-foldout`, `connector` and their dark pairs, and map the radii and shadow to tokens.
- **[medium]** The typography ramp is incomplete for build. Source Serif 4 is decided for "page and section headings", but no token exists for either; only `display-front`, `company-name` and `card-title` do. Phone sizes live in YAML comments, which no resolver reads. Components carry raw sizes: search 20/16px, fold-out header 13.5px, own vs beste fjerdedel 18px, source line 12.5px, tag 11.5px, funnel count 24px, small-card amount 22px. "Heading sizes may need retuning" leaves the ramp open (DESIGN frontmatter `typography`; Typography; Components). *Fix:* add `heading-page`, `heading-section` and `-phone` variants as tokens, and replace the raw px values in Components with token references.

## 3. Component coverage — adequate
27 components are named in DESIGN Components. 26 of them have a behavioural row in EXPERIENCE Component Patterns with real rules, including state handling, FR citations and keyboard behaviour. shadcn primitives are declared as used as-is.
### Findings
- **[medium]** "Banner" is used as a component but has no spec in either file. The widened-band state shows a "banner" with an action ("Tilbake til standard (0,5–2×)"), and Colors and `rounded.md` style "banners". Meanwhile State block claims "widened group" and allows "at most one link". A developer cannot tell whether the widened notice is a State block or something else (DESIGN Components → State block; EXPERIENCE State Patterns → Widened size band; Size-band control). *Fix:* either define Banner in both spines, or state that the widened notice is a State block and its action is that block's one link.
- **[low]** Header has a DESIGN row and a `header` token but no Component Patterns row. Its behaviour (search hidden on the front page, link target) lives only in IA bullets (EXPERIENCE Component Patterns). *Fix:* add a Header row.
- **[low]** Several sub-parts are mentioned but never specified: the compact peer list under the beeswarm (DESIGN gives no visual), the beeswarm legend, the "Vis tallene" table, the waterfall reference tag, how the data-quality flag looks inside the provenance drill-down, the "Slik fungerer det" steps, and the About page's table of contents (DESIGN Components; EXPERIENCE Component Patterns). *Fix:* give each one line inside its parent's row.

## 4. State coverage — adequate
Walked seven surfaces: Forside, Oversikt, Peers, Nøkkeltall og gap, Verdi, Uncovered result, Slik fungerer Peerless. Covered: below floor, outside seed, uncovered, not in database, no match, malformed, FR-71, non-small subject, adjusted group, widened band, above and below median, empty multiple, strength, rate limit, loading, lookup error, measurement pending, focus, reduced motion. Offline is reasonably left to the browser.
### Findings
- **[high]** There is no treatment for invalid or stale URL state. The technical note requires every URL value to be "validated on each request rather than trusted". Uncovered cases: an excluded orgnr that is not in the group (for example a peer removed under FR-66), a closable share that is not a step, a multiple that is ≤ 0 or not numeric, an out-of-range size step, and an unknown tab. FR-69's "reproduces the same analysis" also has no rule for a URL created before a batch refresh (EXPERIENCE Interaction Primitives → URL is state; State Patterns). *Fix:* add a state row. For example: invalid parameters fall back to their default and a tag says so. A newer filing year than the URL implies is shown with the header's data date.
- **[high]** Oversikt's hero and small cards have no empty treatment. Unhandled cases: the subject is at or above beste fjerdedel on every kroner figure (no largest gap); only one gap exists (no "Nest største gap"); nothing lacks a basis ("Mangler grunnlag"). These are the primary surface's first elements (EXPERIENCE Component Patterns → Hero card, Small card). *Fix:* specify the copy and layout for each, for example the hero turns to the largest strength with "▲ Styrke" and no kroner.
- **[medium]** An undefined own value (FR-23 and FR-24: zero or negative denominator, or a component that cannot be derived) has no row treatment. The per-figure count of companies left out of the distribution, which FR-23 requires to be shown, is ambiguous: the benchmark row subline reads "direction · count" (EXPERIENCE State Patterns; DESIGN Components → Benchmark row). *Fix:* add an "own value undefined" row with copy, and define the count in the subline as peers used and peers left out.
- **[medium]** The Verdi page misses two states. When driftsmargin is a strength, the profit amount card has no treatment; the only no-target copy is "Ikke beregnet – for få…". Invalid multiple input (0, negative, text, comma decimal) is also untreated (EXPERIENCE Component Patterns → Amount card, Multiple field). *Fix:* add both.
- **[medium]** Recompute (FR-19) has no in-progress or failure state for exclude, restore, widen or step changes. Whether recompute is a server round trip is unstated, so loading and error behaviour is undefined (EXPERIENCE Interaction Primitives → Immediate recompute). *Fix:* commit to client-side or server-side recompute, and give the pending and failed treatment.
- **[medium]** The Peers surface has no treatment when the whole group is thin: fewer than 10 peers after stage 5, still too few at 0,25–4×, or zero peers. Only row-level handling exists (EXPERIENCE State Patterns; Component Patterns → Funnel, Size-band control). *Fix:* add a surface-level state, for example a State block above the funnel with the widen action.
- **[low]** Seven state copies are still `[ASSUMPTION]`: no match, lookup error, rate limit, loading, FR-71 string, tap targets, beeswarm arrow keys. Submitting an empty search field is untreated (EXPERIENCE State Patterns). *Fix:* confirm the copies, and add the empty-submit case.
